01

从 Clone 到第一次调用

先用最轻的假服务走通全程，再只为需要的真实模型装行李。

新电脑上，先别搬进整座仓库

假设你刚换了一台 GPU 电脑，只想运行 SAM3。普通 clone 只是拿到行李箱，services.yaml 才是装箱清单。

FAKE · 先走通 假模式不取模型、不做重计算，先证明整条链路能工作。
REAL · 再装载 只为选中的服务拉取上游项目、模型权重、CUDA 与依赖。
💡
核心判断

假模式成功，说明“配置 → 启动 → 调用”已经连通；之后真实模式失败，就集中查模型安装，而不是把整条链路一起怀疑。

第一件装备：只选 SAM3

YAML 配置文件就是旅行清单。这个运行配置只写一个服务，并给它加上假模式参数。

CODE 
git clone <robot-tools-url>
cd robot-tools

services:
  - name: sam3
    port: 5558
    extra_args: ["--fake"]
PLAIN ENGLISH

把 robot-tools 代码复制到本机。

进入刚复制的项目目录，后面的命令都从这里执行。

开始列出这次要运行的服务。

清单里只放 sam3，不会顺便选择其他模型。

端口 5558 是它对外等待请求的门牌号。

额外参数 --fake 要求先启动轻量假服务。

前 15 分钟：把安装和调用拆开

下面的 CLI 生命周期像一条检查路线。先走轻量路线，确认无误后再拐进真实模型路线。

CODE 
uv run robot-tools sync      # exact locked light/fake venvs; no upstreams or weights
uv run robot-tools install   # selected upstreams and locked real dependencies
uv run robot-tools download  # selected model artifacts
uv run robot-tools doctor    # read-only local checks
uv run robot-tools launch    # selected HTTP servers
PLAIN ENGLISH

sync 创建严格锁定的轻量／假虚拟环境，不取上游和权重。

install 只为已选服务准备真实依赖、补丁与原生构建；需要时也会处理子模块。

download 只下载已选模型的产物。

doctor 只读取本机状态并报告问题，不修改环境。

launch 启动选中的 HTTP 服务器，开始等待调用。

sync、install、download、doctor 和 launch 默认读取当前目录的 services.yaml；只有使用另一份 profile 时才需要在命令后写路径。

Aha：contract 是双方共用的“兼容护照”

它的 schema 同时约束请求和响应；任意一端偷偷换格式，护照检查就会暴露问题。

200 已签收：请求处理成功，可以继续检查结果内容。
422 清单不合格：请求没通过 schema 检查，通常还没进入 handler。
500 办理中出错：服务端内部失败，查看 handler 或 backend 日志。这里的数字叫 status code。

真实代码：寄件端先整理，再封箱

新建一张名为 ReconstructRequest 的寄件单。

右图也执行完全相同的本地整理。

把有效迭代次数原样写进寄件单。

把最大视差限制也写进去。

请求模型装填完成。

CODE · wire.py 
def pack(payload: object) -> bytes:
    return msgpack.packb(payload, default=msgpack_numpy.encode, use_bin_type=True)

def unpack(raw: bytes) -> object:
    return msgpack.unpackb(raw, object_hook=msgpack_numpy.decode, raw=False)
白话翻译

定义 pack：输入一个 payload 对象，输出字节。

MessagePack 负责封箱；msgpack_numpy 专门处理 NumPy 数据。

两种方向在这里对称相遇。

定义 unpack：输入原始字节，输出对象。

MessagePack 负责拆箱；NumPy 解码助手把数组恢复回来。

真实代码：收件端只处理自己的那一棒

FastFSServer 不负责网络封箱；它接到合格请求后，决定走假结果还是调用真实 backend。

CODE · server.py 
@handler(ReconstructRequest)
def reconstruct(self, req: ReconstructRequest) -> ReconstructResponse:
    if self._fake:
        H, W = req.left.shape[:2]
        return ReconstructResponse(disparity=np.zeros((H, W), dtype=np.float32))

    disp, _timings = self.backend.infer(
        req.left,
        req.right,
        valid_iters=req.valid_iters,
        max_disp=req.max_disp,
    )

sync 会主动撕掉旧检车贴

light 与 real 共用 venv，所以“曾经 install 成功”不能永久作数。代码先清除 real marker，再按当前 lock 精确同步；就算同步中途失败，也不会留下虚假的“可跑 real”状态。

CODE 
def _sync_one(spec: ServiceRuntimeSpec, extras: list[str]) -> None:
    # The lightweight and real projects intentionally share one .venv. Clear
    # the real marker before exact sync starts because even a failed sync may
    # have partially removed real-only packages.
    clear_real_install(spec.runtime_dir)
    cmd = ["uv", "sync", "--locked"]
    for e in extras:
        cmd.extend(["--extra", e])
    extras_str = " ".join(f"--extra {e}" for e in extras) or "(no extras)"
    logger.info("[sync] %s: uv sync --locked %s (cwd=%s)", spec.service_id, extras_str, spec.runtime_dir)
    env = os.environ.copy()
    env.pop("VIRTUAL_ENV", None)
    subprocess.run(cmd, cwd=spec.runtime_dir, env=env, check=True)
PLAIN ENGLISH

这个函数接收一项服务规格和可选 extras。

注释说明 light 与 real 故意共用一套 venv。

即使 sync 失败，也可能已经删掉一部分 real 专用包。

因此第一步就清除 real 检车贴，绝不让旧状态冒充成功。

准备 uv sync --locked，要求严格服从锁定版本。

把 profile 选中的每个 extra 加入命令。

把 extras 整理成可读文字，方便日志说明这次同步了什么。

记录服务、extras 与工作目录，排错时能还原现场。

复制环境变量，再移除外部 VIRTUAL_ENV 干扰。

在当前 runtime 目录执行命令；只要失败就立即报告。

SERVICE_ID = "fastfs"
API_VERSION = "1"
ACTIONS = frozenset({"reconstruct"})

class ReconstructRequest(BaseRequest):
    action: Literal["reconstruct"] = "reconstruct"
    left: np.ndarray  # (H, W, 3) uint8 or (H, W) gray; client coerces to HxWx3 uint8

    valid_iters: int | None = None

left 和 right 是左右图；client 会把灰度图整理成统一的三通道 NumPy 数组。

valid_iters 和 max_disp 都是可选整数。

@handler(ReconstructRequest)
def reconstruct(self, req: ReconstructRequest) -> ReconstructResponse:
    if self._fake:
        H, W = req.left.shape[:2]
        return ReconstructResponse(disparity=np.zeros((H, W), dtype=np.float32))

    disp, _timings = self.backend.infer(
        req.left,
        req.right,
        valid_iters=req.valid_iters,
        max_disp=req.max_disp,
    )
    return ReconstructResponse(disparity=disp)

def test_install_initializes_only_services_in_profile(tmp_path, monkeypatch):
    profile = _write(tmp_path, "services:\n  - name: sam3\n  - name: fastfs\n")
    initialized = []
    synced = []
    scripts = []
    monkeypatch.setattr(launcher, "_init_upstream", lambda spec: initialized.append(spec.service_id))
    monkeypatch.setattr(launcher, "_sync_one", lambda spec, extras: synced.append((spec.service_id, extras)))
    monkeypatch.setattr(
        launcher,
        "_run_runtime_script",
        lambda spec, script: scripts.append((spec.service_id, script)),
    )

    launcher.install(Path(profile))

    assert initialized == ["sam3", "fastfs"]
    assert synced == [("sam3", []), ("fastfs", [])]
    assert scripts == [("sam3", "install.sh"), ("fastfs", "install.sh")]
