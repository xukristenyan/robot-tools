读懂一个已经接好的扩展包

foo 还不存在，所以先把 fastfs 当作参照物。看清三处接缝：contract 定规则，client 声明自己听得懂，server 把规则接到实现。

① contract：身份、动作与数据形状

CODE · src/robot_tools/services/fastfs/contract.py 
SERVICE_ID = "fastfs"
API_VERSION = "1"
ACTIONS = frozenset({"reconstruct"})

class ReconstructRequest(BaseRequest):
    action: Literal["reconstruct"] = "reconstruct"
    left: np.ndarray  # (H, W, 3) uint8 or (H, W) gray; client coerces to HxWx3 uint8
    right: np.ndarray  # same shape as left
    # Per-call refinement knobs; None => use server's startup defaults.
    valid_iters: int | None = None
    max_disp: int | None = None

class ReconstructResponse(BaseResponse):
    disparity: np.ndarray  # (H, W) float32, in pixels — depth = K_fx * baseline / disp
白话翻译

服务身份证写着 fastfs；它说第 1 版API，只接受 reconstruct 动作。

定义“重建请求”这种数据结构。

Literal 把动作锁定为 reconstruct；调用者不能传别的词。

left 和 right 是左右图；client 会把灰度图整理成统一的三通道 NumPy 数组。

注释说明下面两个旋钮每次调用都能改；传 None 就使用服务启动时的默认值。

valid_iters 和 max_disp 都是可选整数。

响应只承诺返回 disparity 数组，并把尺寸、类型和单位写清楚。

② client：公开兼容承诺

CODE · src/robot_tools/services/fastfs/client.py 
class FastFSClient(BaseClient):
    SUPPORTED_SERVICE_APIS: ClassVar[dict[str, frozenset[str]]] = {SERVICE_ID: frozenset({API_VERSION})}
    REQUIRED_ACTIONS = ACTIONS
白话翻译

FastFSClient 复用所有服务共有的基础 client 能力。

它公开声明“我支持 fastfs 的这一版 API”，并要求服务至少提供 contract 列出的全部动作。

③ server：同一入口，fake 与 real 两条路

CODE · runtimes/fastfs/server.py 
@handler(ReconstructRequest)
def reconstruct(self, req: ReconstructRequest) -> ReconstructResponse:
    if self._fake:
        H, W = req.left.shape[:2]
        return ReconstructResponse(disparity=np.zeros((H, W), dtype=np.float32))

    disp, _timings = self.backend.infer(
        req.left,
        req.right,
        valid_iters=req.valid_iters,
        max_disp=req.max_disp,
    )
    return ReconstructResponse(disparity=disp)
白话翻译

装饰器把 ReconstructRequest 接到 reconstruct 函数。

函数承诺：输入是重建请求，输出是重建响应。

fake 模式不加载真实模型，只按输入图片尺寸造一张全零结果。

这样普通开发机也能快速验证请求、响应和网络接线。

real 模式把左右图和每次调用的选项交给 backend 推理。

backend 返回结果与计时；这里只需要 disparity。

最后用 contract 规定的响应类型把真实结果送回去。

foo 的施工单：文件一个都别漏

下面是新增服务的最小完整清单。文件名可以参考现有服务，责任边界不能靠复制猜出来。

1
固定上游来源

runtimes/foo/upstream/ 放固定版本的上游源码；若用 Git submodule，同步登记根目录的 .gitmodules。

2
先建公开契约

src/robot_tools/services/foo/contract.py 定义 SERVICE_ID、API_VERSION、ACTIONS、请求和响应；这里不 import 重型模型库。

3
补 client 与导出入口

client.py 做方便调用与输入整理；__init__.py 对外导出 FooClient、请求和响应类型。

4
搭好独立 runtime

runtimes/foo/server.py 接请求，backend.py 既加载真实模型，也做统一适配器；根 pyproject.toml + uv.lock 锁定轻量 fake 环境，real/pyproject.toml + real/uv.lock 单独锁定真实重依赖。

5
让安装与诊断可重复

install.sh、download.sh、doctor.py、可选 compat/ 分别管环境、资源、诊断和兼容；安装/下载可执行脚本要保留执行权限，并补 README.md、PREREQUISITES.md。

6
登记启动与连接资料

src/robot_tools/registry.py 这份注册表登记 foo 的 runtime 目录、启动命令、GPU 要求和唯一默认端口；services.example.yaml 补启动 profile，endpoints.example.yaml 补调用方的 endpoint 样例。

7
留下用法与证据

examples/ 给最小调用，tests/ 覆盖 contract、client、fake server 和真实探针，docs/ 写安装、版本、排错与限制。

“完成”不是文件齐了，而是证据齐了

下面这份完成定义可以直接放进任务单。它把“看起来能跑”变成别人也能复查的结果。

📏

契约稳定

service id、API version、actions、字段形状/类型/单位明确；关键不变量在 fake 与 real 路径一致。

🪶

边界干净

公共 SDK client 不 import 模型库；Torch、CUDA 和上游依赖只留在 runtimes/foo。

🔧

安装可重复

新环境按文档可安装；锁文件同步；脚本有执行权限；下载重复运行不会破坏已有资源。

🚦

登记无冲突

registry、endpoint 样例和文档中的 service id / port 一致，默认端口不与现有服务相撞。

🧪

两级验证

fake 测试在无 GPU 环境通过；real probe 在支持的机器上得到合理结果。

🧾

验收可复查

验收测试、运行命令、输出摘要、限制与未验证项全部写明。

可复用 AI Prompt

复制后替换大括号内容

目标：为 robot-tools 新增 {SERVICE}，主要动作是 {ACTION}，参考 {REFERENCE_SERVICE} 的结构，但先比较差异，不要整目录盲拷。

公共 API：先在 src/robot_tools/services/{SERVICE}/contract.py 定义 service id、API version、actions、请求/响应；写清数组形状、类型、单位、可选字段与默认行为。再实现 client，并更新 __init__.py 导出。

runtime：在 runtimes/{SERVICE}/ 隔离所有重依赖；实现 server 的 fake/real 分支与 backend 上游适配，分别维护轻量根 lock 和 real/ 重依赖 lock，并补安装/下载/doctor/compat、README 与 PREREQUISITES。脚本必须可执行且可重复运行。

接线：更新 registry、services.example.yaml 与 endpoints.example.yaml，分配未占用端口；补 examples、docs、contract/client/fake 测试和真实 probe。

验收：根 SDK 不新增模型依赖；fake 无 GPU 通过；real probe 返回符合 contract 的 {EXPECTED_SHAPE_AND_DTYPE}；列出修改文件、运行命令、结果、风险与未验证项。若有不兼容变化，说明版本升级与迁移方案。

⚠️
不要让 AI 用“复制成功”冒充“接入完成”

要求它报告每条验收证据，并明确哪些 real 检查因为没有硬件而尚未执行。诚实的未验证项，比一条含糊的“测试通过”更有价值。

架构情境演练：你来做接入负责人

这里没有背文件名的题。每题都要求你守住边界、兼容性和可验证性。

情境 1 · 相机转换

某机器人使用专有 DepthCam 对象，而 foo 的 contract 接受 NumPy 图像数组。这个转换应放在哪里？

情境 2 · 两种选项

foo 有固定的模型权重路径，也有每张图都可能不同的 score_threshold。怎样分配最清楚？

情境 3 · 上游导入失败

fake 测试通过，但 real server 启动时报 ModuleNotFoundError: foo_model。第一轮修复范围是什么？

情境 4 · 不兼容升级

团队决定把响应字段 masks 改名为 segments，旧 client 不能自动适配。应该怎样发布？

情境 5 · 端口碰撞

foo 默认使用 5558，但 sam3 已占用它。怎样处理才算完成？
