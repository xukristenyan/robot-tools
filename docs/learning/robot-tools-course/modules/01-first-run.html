01

从 Clone 到第一次调用

先用最轻的假服务走通全程，再只为需要的真实模型装行李。

新电脑上，先别搬进整座仓库

假设你刚换了一台 GPU 电脑，只想运行 SAM3。普通 clone 只是拿到行李箱，services.yaml 才是装箱清单。

FAKE · 先走通 假模式不取模型、不做重计算，先证明整条链路能工作。
REAL · 再装载 只为选中的服务拉取上游项目、模型权重、CUDA 与依赖。
💡
核心判断

假模式成功，说明“配置 → 启动 → 调用”已经连通；之后真实模式失败，就集中查模型安装，而不是把整条链路一起怀疑。

第一件装备：只选 SAM3

YAML 配置文件就是旅行清单。这个运行配置只写一个服务，并给它加上假模式参数。

CODE 
git clone <robot-tools-url>
cd robot-tools

services:
  - name: sam3
    port: 5558
    extra_args: ["--fake"]
PLAIN ENGLISH

把 robot-tools 代码复制到本机。

进入刚复制的项目目录，后面的命令都从这里执行。

开始列出这次要运行的服务。

清单里只放 sam3，不会顺便选择其他模型。

端口 5558 是它对外等待请求的门牌号。

额外参数 --fake 要求先启动轻量假服务。

前 15 分钟：把安装和调用拆开

下面的 CLI 生命周期像一条检查路线。先走轻量路线，确认无误后再拐进真实模型路线。

CODE 
uv run robot-tools sync      # exact locked light/fake venvs; no upstreams or weights
uv run robot-tools install   # selected upstreams and locked real dependencies
uv run robot-tools download  # selected model artifacts
uv run robot-tools doctor    # read-only local checks
uv run robot-tools launch    # selected HTTP servers
PLAIN ENGLISH

sync 创建严格锁定的轻量／假虚拟环境，不取上游和权重。

install 只为已选服务准备真实依赖、补丁与原生构建；需要时也会处理子模块。

download 只下载已选模型的产物。

doctor 只读取本机状态并报告问题，不修改环境。

launch 启动选中的 HTTP 服务器，开始等待调用。

sync、install、download、doctor 和 launch 默认读取当前目录的 services.yaml；只有使用另一份 profile 时才需要在命令后写路径。

你的“前 15 分钟”清单

1
Clone 项目

只拿代码，不把所有模型都搬过来。

2
写一项配置

services.yaml 只选 sam3，并保留 --fake。

3
运行 sync

先得到可重复的轻量环境，把环境问题单独解决。

4

5
检查 status

确认下游看到的是正确服务地址。

拿到假结果后，再决定是否进入真实安装路线。

另一台电脑只做调用，不必重装模型

下游项目安装 SDK，再从 endpoint 配置中找服务器。这样模型电脑负责运行，下游笔记本只负责发请求。

CODE 
uv add --editable /path/to/robot-tools
cp /path/to/robot-tools/endpoints.example.yaml endpoints.yaml
uv run robot-tools status endpoints.yaml

from robot_tools.core.endpoints import get_endpoint
from robot_tools.services.fastfs import FastFSClient

client = FastFSClient.from_endpoint(get_endpoint("fastfs", "endpoints.yaml"))
PLAIN ENGLISH

把本地 robot-tools 以可编辑方式加入下游项目。

复制地址模板，生成这个项目自己的 endpoints.yaml。

先运行 status，确认配置中的服务地址能被看到。

导入读取地址的函数 get_endpoint。

导入 FastFS 的客户端类。

从配置找到 fastfs 地址，再创建可调用的 client。

模型服务器运行真实模型与 API。
下游笔记本保留 SDK 与 endpoints.yaml，不需要复制服务器的权重和 CUDA 环境。
服务器搬家更新 endpoint 的主机与端口，再用 status 验证。

情境演练：你会怎么做？

不考缩写，只考下一步判断。每题先选最稳妥的行动，再查看反馈。

1. 新 GPU 电脑只需要 SAM3，最稳妥的第一轮是什么？

2. 假服务调用成功，但切到真实 SAM3 后失败，应该先怎么缩小问题？

3. 同事的下游笔记本只负责调用模型服务器，应该准备什么？

4. 模型服务器搬到另一台主机，下游调用失败，第一处该改哪里？

🧭
带走这一条排错路线

先证明轻量链路，再装真实模型；地址变化查 endpoint，真实计算失败查 install、download 与 doctor。
